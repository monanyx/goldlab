I built a gold-trading bot, then tried hard to prove it wrong.

goldlab is an automated research lab and a live paper-trading bot. Every strategy had to pass rules I wrote down before seeing any results, including a test on two years of price data that no earlier run had touched. None passed, and the lab caught that before any real money was at risk.

How every strategy was tested

Backtests are easy to fool. Each step below exists to catch a different way of fooling yourself.

Fix the rules first

Hypotheses, parameter grids and the pass/fail rule were committed to git before any real-data run (round 1, round 2).

Stress the recent data

Oct 2024 – Nov 2026: in-sample vs out-of-sample, rolling walk-forward re-tuning, double trading costs, and every nearby parameter setting.

Untouched holdout

Two older years no earlier run had used. Default settings, run once. No second chances.

Prove the bot = the backtest

The live bot's exact code is replayed over real data (fresh process per run, saved state, late and skipped runs) and must produce identical trades.

Round 2: a bot that reads the market first

At the London open the regime switch labels the day (trend, range or chaos) from data known at that moment, then trades a breakout with the trend, fades a false break, or stays out.

Result: not adopted (2 of 7 pre-registered checks passed). Range-day fades were the problem: price that faked out of the Asia range usually kept going.

The live bot

goldbot runs on GitHub Actions throughout the London and New York sessions. It pulls live prices, runs the same engine as the backtests, sends Telegram alerts and paper-trades. Risk rules are enforced in code and can't be loosened by configuration:

  • every order has a stop loss; 1% risk per trade, sized down, never up
  • 3% daily loss limit, at most 3 trades a day, no new trades after 20:00 Vienna time
  • kill switch from Telegram (/stop), a GitHub variable or the config file
  • a broker adapter that can only reach a demo account

What I took from it

  • A good-looking backtest proves very little. London breakout looked fine on 2024–26 and lost on 2022–24. Only data you haven't seen can tell those apart.
  • Deciding the rules first is what makes a "no" trustworthy. Because the pass/fail rules were committed beforehand, the negative result can't be argued away, and the bot stays in paper mode.
  • The backtest and the live system have to be the same code. One engine runs both, and a replay test proves they agree trade for trade.
